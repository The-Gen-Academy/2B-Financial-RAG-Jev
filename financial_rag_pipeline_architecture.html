② Chunking Strategy — Two Parallel Paths
Path A — Fixed-Size Chunking
✂️ RecursiveCharacterTextSplitterchunk_size=512 · overlap=64 tokens
📌 Hard boundaries, uniform chunksSimple, fast, predictable
🗄️ Pinecone: namespace="fixed"Stores all fixed-size chunk vectors
Path B — Semantic Chunking
🧠 LangChain SemanticChunkerSplits on embedding distance breaks
📌 Topic-aware, variable-length chunksRespects meaning boundaries
🗄️ Pinecone: namespace="semantic"Stores all semantic chunk vectors
↓
③ Embedding — Shared for Both Paths

④ Retrieval Quality Evaluation — Pick the Best Chunking Strategy
Fixed-Size Results
10 evaluation questions → top-3 retrieval from Pinecone "fixed" → score with RAGAS (context precision, recall)
VS
Semantic Results
Same 10 questions → top-3 from "semantic" → RAGAS evaluation
🏆 Winner Selected — used in reranking phase below
Whichever strategy has higher context precision + recall moves forward (usually semantic wins on financial docs)
